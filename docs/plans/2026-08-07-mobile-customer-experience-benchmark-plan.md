# 情报站 × AI HOT 界面与客户体验对标方案

> 日期：2026-08-07  
> 范围：全球互联网百晓生与 `https://aihot.virxact.com/` 的公开页面、当前模板和线上生成物。  
> 目标：优先解决手机端阅读困难，再提升内容发现、回访和长期使用体验。

## 一、结论

当前手机端问题的根因不是“缺少响应式 CSS”，而是**把桌面端完整情报工作台压成一列，同时把 90 天事件、日期面板、周报、月报、公司索引、更新日志和反馈全部塞进一个 HTML**。

现有 `@media` 只完成了“布局不横向溢出”，没有完成“移动阅读产品化”：

- 主导航 7 个入口横向滚动；
- 日期导航位于今日事件列表之后，手机用户需读到底才能换日期；
- 周报/月报档案位于正文之后，需滚完整期才能切换；
- 事件卡的标签列在手机端仍保持纵向排列，标题被推到后面；
- 页面切 tab 不改 URL、不记录状态、不回到顶部，浏览器返回键无法承担导航；
- 所有隐藏 tab 和历史数据仍在首屏 HTML 中下载、解析并进入 DOM。

因此，第一阶段不应先调颜色、字号或圆角，而应先减载、重排移动端阅读路径。

## 二、量化证据

### 本站线上首页

2026-08-07 实测：

- 压缩传输约 `816 KB`；
- 解码 HTML 约 `6.87 MB`；
- `1,450` 个链接；
- `982` 个事件卡节点；
- `122` 个历史/折叠卡节点；
- `0` 张图片。

本地生成物 `docs/index.html` 同样约 `6.4 MB`。生成逻辑同时输出：

1. 90 天全部事件 DOM；
2. 90 天日期面板 JSON；
3. 周报/月报档案；
4. 公司索引、更新日志和反馈。

这会造成重复数据和超大 DOM，是手机端慢、长、难导航的结构性原因。

### AI HOT 首页

同日公开页面实测：

- 压缩传输约 `90 KB`；
- 解码 HTML 约 `309 KB`；
- `126` 个链接；
- `19` 张图片。

AI HOT 也存在页面偏长、部分内容重复和图片请求增加的问题，但它把“精选、全部、热点榜、日报、主题、详情”拆成独立路由，单页任务更明确。

## 三、核心对标差距

| 体验维度 | 全球互联网百晓生 | AI HOT | 判断 |
|---|---|---|---|
| 产品定位 | 非中美互联网行动信号与趋势判断 | 广义 AI 新闻聚合与精选 | 本站定位更窄、更有决策价值，不应照搬广义资讯分类 |
| 首页任务 | 今日、历史、报告、公司、运维内容同页承载 | 精选首页聚焦发现重点 | 本站首屏任务过多 |
| 信息分层 | 精选/重点/观察 + 为什么重要/影响 | 精选/全部/热点 + 热度/推荐理由 | 本站判断层更强，应保留 |
| 页面架构 | 单个静态 HTML 内含所有栏目与 90 天数据 | 多页面独立路由 | 本站是移动端性能和导航问题的首要根因 |
| 手机导航 | 7 个 tab 横向滚动 | 核心入口收敛为精选/全部/日报/更多 | 本站缺少移动端主次关系 |
| 日期切换 | 今日页日期导航在正文之后 | 日期、今天/更早、前后日靠近内容入口 | 本站手机端换日期成本过高 |
| 卡片扫读 | 多个标签纵排后才到标题，解释字段全部展开 | 时间/来源/标题/摘要形成时间流 | 本站卡片在手机端缺少“标题优先” |
| 详情体验 | 卡片直接跳外部原文 | 站内详情含 AI 导读、推荐理由、来源、事件后续 | 本站缺少连续阅读和来源聚合 |
| 发现机制 | 地区、公司、关键词 | 内容类型、来源、热点、主题 | 本站适合补“信号类型/行动类型”，不必复制模型/论文等泛分类 |
| 留存机制 | RSS、反馈 | 收藏、主题、日报/周报/月报、事件后续 | 本站只有订阅，没有跨设备阅读状态和主题跟踪 |
| 报告阅读 | 主线、目录、详情折叠做得较好 | 日期、条数、预计阅读时长、栏目目录 | 本站可补阅读成本提示与移动档案切换 |

## 四、改进优先级

## P0：先解决手机端可用性与首屏负载

### P0-1 拆分单页负载

保持 GitHub Pages 和静态生成，不引入重型前端框架：

- `/`：只输出今日判断、今日合格事件、最近报告入口；
- `/weekly/`、`/monthly/`：分别输出报告页；
- `/companies/`：公司索引；
- `/archive/`：90 天事件库；
- `/updates/`、`/feedback/`：低频功能独立页；
- 历史日期按 `data/daily/YYYY-MM-DD.json` 或按日 HTML 分片，用户选择日期后再加载；
- 首页不再内嵌 `datePanels` 全量 JSON，不再渲染 90 天隐藏 DOM。

建议首页目标：

- 解码 HTML `< 500 KB`；
- 初始事件节点 `< 40`；
- 初始可交互链接 `< 200`；
- 不在首页下载 90 天历史和全部报告档案。

### P0-2 重做移动端主导航

手机端只保留四个一级入口：

- 今日
- 周报
- 公司
- 更多

“月报、全部事件、更新日志、反馈、RSS”进入“更多”；搜索与筛选作为今日页工具，不与主导航争夺空间。可采用底部固定导航或顶部固定紧凑导航，需处理 `safe-area-inset-bottom`。

桌面端可以保留完整导航，但应把更新日志、反馈、RSS归入次级区域。

### P0-3 重排移动端今日页

手机阅读顺序：

1. 日期 + 前后日切换；
2. 一句话今日判断；
3. 精选数量和预计阅读时长；
4. 精选事件；
5. 重点事件；
6. “展开观察事件”；
7. 周报/月报入口。

当前侧栏里的日期导航要在手机端移动到事件列表之前；报告摘要卡不应占据首屏。

### P0-4 移动事件卡“标题优先”

移动版卡片改为：

- 第一行：优先级 + 地区/公司（最多 2 个标签）；
- 第二行：标题；
- 第三行：一句“为什么重要”；
- 第四行：来源 + 时间/金额 + 打开原文；
- “影响、原题、关联信源”默认折叠或进入详情。

要求：

- 标签横向、可换行，不再纵向堆叠；
- 正文最小 `16px`，行高约 `1.65`；
- 可点击区域至少 `44px`；
- 标题与正文不得因来源长文本产生横向溢出；
- 精选卡可完整展示，重点/观察卡可压缩摘要。

### P0-5 修复导航状态

- 页面/栏目切换必须有真实 URL 或 hash；
- 支持刷新后保留当前位置；
- 浏览器返回键可以返回上一个栏目；
- 切栏目默认滚到该栏目顶部；
- 日期、报告期次和筛选条件可以复制链接分享。

## P1：提升阅读效率和连续使用

### P1-1 增加站内事件详情页

详情页不是复制原文，而是承接本站价值：

- 中文标题和原题；
- 一句话事实摘要；
- 为什么重要；
- 影响对象；
- 证据与来源层级；
- 同一事件的关联信源；
- 对应公司、地区、趋势；
- 原文按钮；
- 相关后续事件。

这样可避免每次点击都离站，并为收藏、分享和事件线聚合提供载体。

### P1-2 报告移动阅读增强

- 报告顶部显示“X 个主题 · 预计 X 分钟”；
- 期次选择器置于正文前并可横滑/下拉；
- 目录吸顶，支持“回到目录”；
- 主题先展示判断和后续观察，证据继续折叠；
- 上一期/下一期放在报告底部。

### P1-3 筛选改为任务型

本站不复制 AI HOT 的“模型/论文/教程”分类，改为更符合客户决策的问题：

- 行动类型：扩张、合作、采购信号、资本、组织变化、合规；
- 地区；
- 公司；
- 优先级：精选/重点/观察；
- 时间范围。

手机端使用“筛选”按钮打开底部抽屉，并显示已选条件数量。

### P1-4 建立阅读闭环

先做无需账号的本地能力：

- 标记已读；
- 稍后读；
- 复制摘要；
- 分享当前事件/报告深链；
- 恢复上次阅读位置。

跨设备同步、账号体系后置，避免过早增加系统复杂度。

## P2：形成差异化客户体验

- 公司关注列表与“7/30 天发生了什么”；
- 主题/趋势关注，而不是泛新闻主题；
- “自上次访问后的新增重要信号”；
- 每周回顾和月度结构变化的主动提醒；
- 重点事件多信源聚合与证据强度；
- 面向 ICT 从业者的“潜在采购/合作/风险”视图。

不建议优先复制：

- 泛 AI 热点分数；
- 大量内容类型分类；
- 图片驱动的信息流；
- 为了活跃度而加入广义中美 AI 新闻。

这些会稀释本站“非中美 + 可行动情报”的定位。

## 五、实施顺序

### 阶段 1：移动止血

1. 首页只保留今日数据和报告入口；
2. 移动端日期选择前置；
3. 移动端事件卡标题优先；
4. 移动端四入口导航；
5. tab/hash/滚动状态修复。

### 阶段 2：静态多页拆分

1. 提取共享模板片段；
2. 生成 weekly/monthly/companies/archive 独立页面；
3. 历史数据按日分片；
4. 保持 RSS 与当前数据选择器口径不变；
5. 添加页面体积与节点数量回归检查。

### 阶段 3：站内详情与留存

1. 事件详情页；
2. 关联信源和事件后续；
3. 已读/稍后读/分享；
4. 公司与趋势关注。

## 六、验收标准

至少用 `390×844`、`430×932`、`768×1024` 和桌面宽度验证：

- 首屏无需横向滚动；
- 3 秒内能识别日期、今日判断和第一条精选（真实网络性能另行测量）；
- 一屏至少可看到一条完整精选或两条压缩事件；
- 日期切换在首屏或一次滚动内可达；
- 周报/月报期次选择无需先滚完整篇；
- 浏览器返回键和刷新不丢失栏目；
- 所有触控目标不小于 `44×44px`；
- 首页不包含 90 天全部事件 DOM；
- 首页解码 HTML 小于 `500 KB`；
- 搜索、地区/公司筛选、RSS、反馈和外链行为保持正确；
- 周报/月报、日报展示口径不因界面拆分发生变化。
