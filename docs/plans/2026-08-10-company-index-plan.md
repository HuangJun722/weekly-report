# 公司索引改造：企业级情报雷达（实施计划）

> 状态：已定方向，待实施。

## 1. 最终产品定义

一个围绕**核心公司**的变化检测系统：持续监控基本盘公司的重要变化，让用户快速知道「谁动了、发生什么、是否值得进一步关注」。

- **是**：企业级情报雷达。
- **不是**：公司数据库（不止于名录）。
- **不是**：采集监控后台（健康状态不占主位）。

## 2. 最终信息架构（三层）

```
第一层  公司身份   →  为什么它在我的雷达里（分层 + 行业 + 观察方向）
第二层  核心动态   →  最近值得关注事件（标题 + 摘要 + 时间 + 信号类型）
第三层  可信度辅助 →  近30天动态数量 + 采集状态异常角标
```

一句话：**公司身份 → 值得关注的变化 → 情报意义 → 可信度提示。**

## 4. 第一阶段：立即改造（最高优先级）

### 4.1 重构卡片

**删除**：最近检查日期（`last_checked_at`）、覆盖详情（`observation_detail`）、大量统计字段（近7天条数、观察点连接数等）。

**保留 / 重排**：
1. 公司名 + 分层标签
2. **核心动态**：最近值得关注事件（标题 + 一句话摘要 + 时间 + 信号类型）——卡片主体
3. 观察方向一句话（行业标签）
4. 辅助行：近30天数量 + 采集异常角标

### 4.2 建立动态选择算法

**新增字段**：`attention_score`（已有底层实现，补充完整公式）

```
Attention Score = 事件重要性 × 时间衰减 × 公司权重
```

- **事件重要性**：现有 `attention_score` 字段（已实现）
- **时间衰减**：现有日期字段可算（未封装为衰减函数）
- **公司权重**：**缺失**，需新增 —— 核心战略公司（portfolio 分层 must > strategic）加权高于普通观察公司

在 `build_company_cards` 中，每家公司的"最近值得关注事件" = 近30天内 `attention_score` 最高且 `insight_label` 非"观察/背景"的事件。

### 4.3 建立三个采集状态（后台 NORMAL / NO_DATA / PARTIAL_DATA）

把现有 `coverage_status`（active/failed/partial/pending/unverified 等）归一为三态：
- 后台：NORMAL / NO_DATA / PARTIAL_DATA
- 前台：仅在非 NORMAL 时显示「⚠ 数据可能不完整」角标

## 5. 第二阶段：增强能力（今日页公司变化流）

这一阶段独立于前两阶段，可后置。

## 9. 决策记录（2026-08-10 实施时定案）

- **观察方向**：从 sector 自动映射中文标签（`_sector_label` 字典），未用人工维护。后续个别不准可人工补。
- **今日页变化流**：~~本次一并做了（`company_feed`，近2天动态 + 8条上限，点击高亮公司卡片）~~ **已撤回（2026-08-10 用户判定画蛇添足，从今日页移除，相关代码/样式/JS 全清）**。今日页保持聚焦事件流，公司动态统一由公司索引承载。
- **动态标题语言**：**一律中文**（用户明确要求，不用英文增加理解难度）。选取优先级：中文 `summary_short` → `content_overview` → `reason` → 英文 title 兜底。曾误用英文 title（信息完整但增加理解负担），已改回。
- **attention_score 权重系数**：must=1.3 / strategic=1.2 / experiment·mention·watch=1.0；时间衰减 `0.7 ** 天数`。
- **异常角标弱化**：由"非 NORMAL 即显示"改为**仅采集失效(failed)时显示** `coverage_degraded`。
  原因：台账大面积 pending/partial，若全部显示会误导读者"系统全坏"。pending/partial 属过渡态，
  线下由运维侧报告跟踪（采集侧真实状态：32 家仅 12 家闭环，见 entity_observation_ledger.json status_counts）。
- **后续增强（待办）**：修复采集侧缺口，让更多基本盘公司进入闭环，届时角标比例自然下降；
  长期可做第三阶段"战略健康度"（连续 N 天无重要动作触发关注）。
